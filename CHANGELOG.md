# История изменений

Изменения проекта документируются по мере подготовки заметных обновлений.

Формат разделов основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Номера версий следуют Semantic Versioning, когда проект начнёт выпускать формальные версии.

## [Unreleased]

## [0.4.1] — 17 ноября 2026

### Добавлено
- Дело `Leksika где`: печатает, где лежит движок, примеры, словари и документы,
  какая версия Python и каталог пакета, а если команды нет в `PATH` — точный
  каталог скриптов, который нужно добавить. Отвечает на вопрос «куда всё
  поставилось» после `pip install leksika`.
- `python -m leksika_engine` — тот же движок без команды в `PATH`. В Windows
  каталог скриптов pip часто не входит в `PATH`, и это единственный запуск,
  который работает всегда.
- В колесо PyPI попали `программы/` (игры проекта), в установщик Windows —
  `программы/` и `LICENSE`.
- Проверка `packaging/pypi/проверить_состав.py`: сверяет каждый файл движка в
  колесе с исходниками, чтобы пакет на PyPI не оказался урезанным.
- Задание `smoke-python` в `publish.yml`: колесо ставится и запускает пример с
  игрой на Python 3.8 и 3.14.

### Изменено
- Версионный релиз больше не остаётся черновиком: проверка комплекта получает
  черновик из списка релизов (по адресу `releases/tags/<тег>` GitHub отвечает
  404 для черновика) и публикует его. Ночной канал создаётся сразу
  опубликованным.
- `android-smoke` больше не блокирует выпуск: эмулятор в общих раннерах иногда
  не поднимается, а сборка APK и его установка проверяются отдельно.
- Расширение для редактора собирается в `prepare-release` и прикладывается к
  релизу вместе с контрольными суммами.
- Проверка загруженных файлов сверяет SHA-256, когда GitHub его уже посчитал, и
  размер, пока дайджеста нет: загрузка не считается сломанной из-за гонки.

### Исправлено
- Публикация по тегу падала через двадцать секунд после отправки тега: она
  ждала первый запуск `release.yml` для коммита, а это запуск от отправки в
  `main`, где `publish-versioned` пропущен. Теперь ожидание отбирает запуск,
  поднятый самим тегом.

## [0.4.0] — 16 ноября 2026

### Добавлено
- Игры без браузера: `лексика/игры.лек` добавляет в оба исполнителя (дерево и
  учебную машину) 42 игровых действия. Углы и числа: `синус`, `косинус`,
  `тангенс`, `арктангенс`, `пи`, `степень`, `предел`, `наименьшее`,
  `наибольшее`, `знак`, `доля`, `плавно`. Время и случай: `миллисекунды`,
  `посеять`, `жребий`. Векторы: `вектор`, `длинавектора`, `нормальвектора`,
  `скалярноепроизведение`, `векторноепроизведение`, `сложитьвекторы`,
  `вычестьвекторы`, `умножитьвектор`, `повернутьвектор`, `расстояние`.
  Кадр: `холст`, `цвет`, `залить`, `мазок`, `пиксель`, `отрезок`,
  `прямоугольник`, `круг`, `треугольник` с проверкой глубины,
  `сохранитьхолст`. Спрайты: `загрузитьхолст` (чтение PNG с палитрой,
  прозрачностью и всеми фильтрами строк), `вырезать`, `наложить` с прозрачным
  цветом, `смешать`. Перечни: `заменить`, `выбрать`, `перемешать`.
- Горячие игровые действия получили быстрый путь в учебной машине: `синус`,
  `косинус`, `пи`, `предел`, `наименьшее`, `наибольшее`, `знак`, `доля`,
  `заменить` не выходят в медленный совместимый вызов.
- Готовая игровая логика на самой Лексике: `словари/игры.лек` с
  `прямоугольники`, `круги`, `точкав`, `проходимо`, `соседи`, `путьпокарте`
  (поиск пути по клеткам), `вэкран`, `камера`.
- Примеры `примеры/игра_куб.лек` (объёмный вращающийся куб),
  `примеры/игра_змейка.lek` (карта, столкновения, путь) и
  `примеры/игра_спрайты.lek` (набор плиток, чтение PNG, наложение спрайтов).
- Проверки игр в `проверка/тесты.lek`: одинаковый результат в двух движках,
  пиксели холста, чтение чужого PNG (палитра на четыре бита), ошибки с
  подсказками, запуск всех трёх примеров.
- Первый выпуск пакета `leksika` на PyPI: `pip install leksika` ставит
  исполнитель, справку и игровые действия.
- Сквозная автоматизация релиза: по тегу `vX.Y.Z` задание
  `update-package-managers` в `release.yml` обновляет внешние репозитории
  `zmlsaggg/homebrew-leksika` (`Formula/leksika.rb`) и `zmlsaggg/scoop-leksika`
  (`bucket/leksika.json`) версией, ссылками на архивы и SHA-256 из
  опубликованного `zz-SHA256SUMS.txt`, затем коммитит и отправляет изменения в
  `main` сообщением `chore: update leksika to v<версия>`. Задание идёт только
  после успешного `publish-versioned` и пропускает предварительные версии.
- `packaging/update_package_managers.py`: точечная правка формулы и манифеста
  (остальной текст сохраняется), источник сумм — файл или `--download` из
  релиза, `--dry-run`, проверка результата повторным разбором.
- `проверка/менеджеры_пакетов.py`: 17 проверок без сети и секретов — дифф
  только в нужных строках, идемпотентность, отказы на неполные суммы, чужую
  версию и отсутствующий клон, поведение скачивания на локальном сервере.
- `RELEASING.md` и `packaging/README.md`: инструкция про `CROSS_REPO_TOKEN`
  (fine-grained PAT с `Contents: Read and write` только на два репозитория).

### Изменено
- `publish.yml` ждёт не успех всего `release.yml`, а задание
  `publish-versioned`: сбой обновления пакетных менеджеров (например, истёкший
  токен) больше не блокирует публикацию пакета на PyPI.

### Изменено
- Справка ядра `справка` (и `--help`, `-h`, `помощь` как совместимость) больше не
  обещает только «числа и арифметику»: перечислено то, что действительно
  работает нативно — переменные, арифметика, сравнения, логика, ветвления,
  циклы, перечни, правила с параметрами, падежные имена и речь с вставками,
  и честно названо то, что пока выполняет основной исполнитель.
- `проверить_документы` и `русский_cli.py` следят, чтобы в справке не было
  английских флагов и устаревших обещаний.

### Добавлено
- Интерполяция в речи нативного ядра: `речь Здравствуй, (имя)! конец речи`
  вставляет значение выражения прямо в текст. Числа печатаются как обычно,
  логика — словами `да`/`нет`, `ничто` — словом `ничто`, перечень —
  `перечень(1, 2)`, словарь — `словарь(ключ значит значение)`. Двойные скобки
  `((` и `))` дают живые скобки в тексте, пробелы срезаются только по краям
  блока. На уровне байткода это операция `ЛЕКСУС_ОП_В_РЕЧЬ`: во время
  выполнения нет ни разбора, ни склейки строк посимвольно.
- Восемь случаев интерполяции в `контракт-тест` (включая ошибку внутри
  выражения и пустой блок) и пять программ в `сопоставление_движков.py`:
  нативный и эталонный движки обязаны давать одинаковый текст.
- Падежный ввод имён в нативном компиляторе: `сказать суммой`, `длина покупок`,
  `добавить в покупку` работают по тем же правилам склонения, что и
  `лексика/морфология.lek`; диагностика неизвестного имени перечисляет
  заведённые имена, а склонение кэшируется на имя.
- Отдельная проверка `make -C ядро morphology-test` и падежные случаи в
  `компилятор-тест` / `контракт-тест`.
- Страницы «О проекте» и «Контакты»: автор проекта, каналы связи и таблица честного статуса компонентов.
- Раздел «Статьи» с шестью материалами о падежах, переносе движка, границах песочницы, примерах программ и контексте русских языков программирования.
- Сквозная разметка Schema.org: `Organization` с `founder` и `contactPoint` на всех страницах, `AboutPage`, `ContactPage`, `Article` и `FAQPage` на главной.
- Проверка `проверка/сайт_контакты.cjs`: контакты, автор, JSON-LD, карта сайта и внутренние ссылки проверяются в CI.
- Основная команда запуска `Leksika` для Windows, Linux и macOS; старое имя `лексус` сохранено как совместимый псевдоним.
- Документы о безопасности, поддержке и правилах сообщества.
- Метаданные цитирования проекта.
- Публикация переходного исполнителя в PyPI: `pyproject.toml`, запускатор `leksika_engine` и workflow `.github/workflows/publish.yml` с доверенным издателем (Trusted Publishing) и проверкой сумм после загрузки.

### Изменено
- `Leksika` и `Leksika справка` никогда не показывают английских команд;
  `версия` и `справка` стали делами, английские флаги принимаются скрыто.
  Новая проверка `проверка/русский_cli.py` следит за обоими обещаниями.
- `make -C ядро core` собирает только ядро; цель `native` ей синонимична,
  внешний словарь подсказок остаётся необязательным (`make all`).
- `проверка/проверить_документы.lek` проверяет примеры во всех разговорных
  профилях: профильные куски больше не отбрасываются, а отчёт честно называет
  их число (сейчас 20 кусков, 0 ошибок, 2 только в профиле).
- Установщики создают launcher `Leksika`; Windows добавляет каталог программы в пользовательский `PATH`, Linux/macOS устанавливают команду в `~/.local/bin`.
- Улучшена навигация README и удалён искусственный перечень поисковых фраз.
- Уточнено позиционирование проекта и статус незавершённых компонентов.

### Примечания
- `Leksika` пока скрывает запуск переходного Python-исполнителя; нативная VM без Python остаётся отдельной незавершённой задачей.
- Формальные релизы и политика поддержки версий будут объявлены отдельно.
