# Безопасность и конфиденциальность Лексики

Лексика развивается как локальный инструмент. Это направление разработки, а
не сертификат безопасности и не обещание, что любой код на языке автоматически
защищён от утечек.

## Поведение по умолчанию

- Установщик Windows распаковывает встроенный пакет локально. Во время установки
  он не загружает дополнительные компоненты, не отправляет телеметрию и не
  проверяет обновления.
- Установка выполняется в профиль текущего пользователя, без запроса прав
  администратора. Каталог пользователя и системный `PATH` не изменяются.
- Встроенная морфологическая модель работает локально.
- Сетевой поиск из режима беседы выключен по умолчанию. Даже при выбранной
  локальной GGUF/ONNX-модели вопрос не отправляется поисковику автоматически.
- Явное разрешение сетевого поиска:
  `лексус настройка разрешить_поиск_в_сети да`.
  Отключение:
  `лексус настройка разрешить_поиск_в_сети нет`.
  При включении поисковику передаётся текст поискового запроса.
- Внешняя GGUF/ONNX-модель в текущей реализации запускается локально через
  локальный движок. Не помещайте конфиденциальные данные в сторонние облачные
  сервисы или плагины, если отдельно не проверили их политику обработки.

## Важные ограничения

- Текущий исполняющий механизм `.lek` всё ещё использует Python и выполняет
  программы с правами текущего пользователя.
- Язык пока не является песочницей: программа может читать и изменять файлы,
  доступные пользователю, и запускать доступные ему процессы.
- Файлы проекта и настройки пока не шифруются автоматически.
- Нативное ядро C11 ещё не заменило полный интерпретатор и не является
  самостоятельной границей безопасности.
- Проверка структуры пакета установщиком защищает от некорректных имён путей
  и выходов смещений за границы встроенного пакета, но пока не заменяет
  криптографическую подпись и проверку хешей файлов.

**Поэтому текущую версию нельзя считать сертифицированной средой для
секретов, регулируемых данных или критичных производственных систем.**
До такого применения нужны независимый аудит, подпись релизов, проверка
целостности каждого файла, изолированное исполнение с моделью разрешений,
безопасное управление ключами и тесты на Windows/Linux.

## Сообщение об уязвимости

Не публикуйте рабочие секреты, ключи API, персональные данные или содержимое
закрытых проектов в публичных задачах. Для отчёта приложите минимальный
воспроизводимый пример без реальных данных.


## Защищённый режим Лексуса

Теперь у переходного runtime есть отдельная политика доступа. Обычный режим
сохраняет совместимость, а защищённый режим по умолчанию закрывает сеть,
внешние процессы, сторонние Python-модули и файловый доступ вне разрешённых
корней. Аудит в защищённом режиме не отключается.

    лексус безопасность
    лексус безопасность режим защищённый
    лексус безопасность путь ~/Проекты/Банк/приложение
    лексус безопасность аудит
    лексус аудит --проверить

Сетевой поиск имеет двойной opt-in: разрешение сети в политике плюс настройка
разрешить_поиск_в_сети. Конкретный сетевой провайдер подключается отдельно;
DuckDuckGo больше не является частью основного CLI-кода.

Переходный модуль секретов получает значение по имени из окружения и никогда
не пишет само значение в аудит. Это ещё не HSM, DPAPI, Keychain или Secret
Service; нативные backend-хранилища остаются отдельным этапом.

Наш контейнер LEKSUSPK дополнительно проверяет границы записей и не позволяет
распаковать файл за каталог назначения.
