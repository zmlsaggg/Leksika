# Роадмап самостоятельного движка Лексики

Цель: готовый Лексус запускает Лексику без Python у пользователя. C11 остаётся только bootstrap-ступенью до самохостинга.

## Уже закрыто
- Собственные значения и точная десятичная арифметика.
- Регистровая VM, верификатор байткода и лимит шагов.
- `если/иначе`, `пока`, `повторить`, `прервать`, `продолжить`.
- Нативные перечни и обход `где` / `для каждого` с локальной переменной.
- `что`, условная форма `когда`, `почему`; отдельная временная форма `когда ... наступит` диагностируется, но ещё не исполняется.
- В переходной VM — `как <правило>` с аргументами и импорт rule-only модулей через байткод без AST fallback.
- Нативная VM: добавлены кадры вызовов с отдельными регистрами, аргументами, возвратом и лимитом рекурсии; компилятор пока не генерирует эти вызовы.
- Разговорные профили: браузер и native C используют сверяемый общий набор командных синонимов.
- Нативная VM проверяет capabilities ввода/вывода до обращения к среде.
- UTF-8, числительные, базовая морфология и бинарный словарь LEKSLXD1.
- Нативный запуск без Python в PATH для поддерживаемого подмножества.
- Browser playground с отдельными режимами кода/чата, морфологическими подсказками и переключателями разговорных профилей.

## Проверенные результаты

- Linux: полный `make clean all test` и ASan/UBSan прошли.
- Windows: полный MinGW `make clean all test` и Clang ASan/UBSan прошли.
- macOS: полный `make clean all test` и проверка установленного пакета прошли.
- Закреплённый словарь: 1 528 715 уникальных форм из 1 532 628 строк; 41 051 188 байт; CRC32 `78EE39A5`.
- Сжатый индекс размером 6,7 MiB опубликован в `ядро/русские_формы.lxd.gz`; браузер загружает его лениво и проверяет CRC.
- Linux/macOS-установщики собирают индекс из закреплённого submodule; оба пакета проверены на наличие бинарного словаря.
- Differential-набор расширен до общего подмножества с вводом, ветвлениями, циклами и коллекциями; полный охват языка ещё не достигнут.

## Ближайший рывок

### 1. VM 2.0 — подключить кадры к языку
- Подключить нативные кадры вызовов к компилятору: объявления правил, параметры, call-site descriptors и `как <правило>`.
- Ввести лексические области и корректный доступ к глобальным/локальным именам.
- Добавить возврат значений, обработку ошибок и тесты рекурсии уже на уровне исходного синтаксиса.
- Перенести словари и интерполяцию речи.

### 2. Полная лексическая база
- [x] Собирать закреплённый словарь на CI и сохранять фактическую статистику.
- [x] Публиковать сжатый `ядро/русские_формы.lxd.gz` рядом с GitHub Pages.
- [x] Подключить сборку того же ресурса к Linux/macOS-установщику; Linux-пакет проверен, macOS runtime-проверка ещё нужна.
- [ ] Добавить POS/частотность/стилистику только из проверенных источников.
- [ ] Перенести профильные имена и грамматические признаки в native VM; синхронизировать выбор профиля между desktop и browser.

### 3. Естественный синтаксис
- Перенести `как` из переходной VM в нативный компилятор; низкоуровневые кадры уже готовы.
- Реализовать временную форму `когда ... наступит` через явную среду событий.
- Интерполяция речи.
- Падежное разрешение имён и согласование рода/числа/падежа.
- Не превращать неоднозначность в угадывание.

### 4. Стандартная среда
- Файлы через разрешаемые callbacks VM.
- Время, случайность и модули через тот же интерфейс.
- Расширить native capability checks с консольного ввода/вывода на файловые, сетевые, процессные и секретные операции.
- Перенести хранение секретов в OS keychain/DPAPI/Keychain equivalents; добавить OCSP/CRL только при подтверждённой необходимости.

### 5. Удаление переходного слоя
- Один общий differential-набор: переходный исполнитель ↔ native VM.
- Все `.lek` примеры из документации запускаются новой VM.
- Python исключается из обычного запуска и установщиков.
- После этого — самохостящийся компилятор и воспроизводимая сборка.
- Не отключать старый исполнитель, пока общий интерфейс значений и полный набор differential-тестов не достигнут требуемого порога.

## Финальная цель

`Leksika программа.lek` → собственный компилятор → собственный байткод → собственная VM → собственная стандартная среда.

Python и C-компилятор не нужны пользователю.
