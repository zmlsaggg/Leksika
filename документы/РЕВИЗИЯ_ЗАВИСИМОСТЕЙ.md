# Ревизия внешних зависимостей Лексики

Дата ревизии: 11 ноября 2026 года.

## Итог

В проекте нет прямой обязательной зависимости runtime от npm, PyPI, requests,
curl, wget или внешнего облачного API для обычного запуска программы.

Но переходный runtime всё ещё сильно связан с Python, а несколько необязательных
или служебных функций обращаются к иностранным инфраструктурам.

## Что меняется этим PR

### 1. Сеть больше не принадлежит ядру

Основной лексус.lek больше не содержит DuckDuckGo-клиента.

Сеть проходит через лексика/сеть.lek, а конкретный DuckDuckGo-клиент находится
в отдельном необязательном адаптере лексика/провайдеры/duckduckgo.lek.

По умолчанию провайдер — нет, а сетевой доступ выключен политикой.

Для старого пользовательского сценария сеть теперь требует двух явных вещей:

1. разрешить сеть в политике;
2. разрешить поиск в настройках языка.

Это двухступенчатое opt-in, а не скрытый сетевой вызов.

### 2. Защищённый режим

Добавлена политика в ~/.lek/политика.без.

Главный режим:

- обычный — сохраняет совместимость с текущими программами;
- защищённый — ограничивает чувствительные операции.

В защищённом режиме по умолчанию закрыты:

- сеть;
- запуск внешних процессов;
- сторонние внешние Python-модули;
- запись и чтение вне разрешённых корней.

Разрешения выдаются отдельными allowlist.

### 3. Аудит

События записываются в ~/.lek/аудит.логе.

Запись содержит время, действие, объект, результат, причину и SHA-256 цепочку
предыдущей записи. Содержимое секретов никогда не попадает в журнал.

Это пока локальный журнал с защитой целостности, а не неоспоримый серверный журнал:
процесс с правами владельца файла всё ещё способен удалить или заменить файл.

### 4. Секреты

Добавлен модуль лексика/секреты.lek.

Он позволяет программе получать секрет только по имени из окружения и запрещает
показывать значение через CLI лексус секрет ИМЯ.

Для защищённого режима можно составить allowlist разрешённые_секреты.

Это переходный слой. Это ещё не аппаратное хранилище и не замена Windows DPAPI,
Linux Secret Service, macOS Keychain или HSM. Следующий шаг — нативные хранилища
без передачи пароля в Python.

### 5. Архивы

Заодно усилен наш контейнер:

- проверяются количество записей и границы таблицы;
- проверяются смещения и размеры;
- запрещаются абсолютные пути и ..;
- распаковка проверяет, что итоговый путь остаётся внутри каталога назначения.

## Где Python реально остаётся

Переходный слой:

исходник .lek
↓
Python 3
↓
лексер / грамматика / старый исполнитель / переходная VM

При запуске пользовательского кода Python всё ещё является фактической средой
исполнения. Этот PR не притворяется обратным.

Нативная модель значений из PR #11 является отдельным загрузочным модулем и пока не
заменила этот путь.

## Следующая очередь удаления Python

1. Собственный компилятор выражений.
2. Собственный байткод без объектов AST.
3. Полная VM.
4. Нативная файловая среда и загрузчик.
5. Нативный аудит и политика.
6. Перенос лексика/модель.lek, исполнитель.lek и остальных внутренних модулей
   на настоящую Лексику.
7. Удаление встроенного Python из Windows-пакета.
8. Удаление Python из установить.lek и установить.sh.
9. Удаление Python-загрузчика из лексика/загрузка.lek.

## Важное наблюдение по Windows bootstrap

Сейчас сборщик скачивает python-3.12.7-embed-amd64.zip с python.org.
Официальный каталог Python всё ещё содержит этот файл, но ветка 3.12 к 25 октября
2026 года уже достигла версии 3.12.16 и находится в режиме security-only.

Это означает: даже bootstrap уже не должен быть постоянной архитектурой. Мы не
обновляем его здесь наугад, чтобы не сломать текущую переходную среду; правильное
решение — сделать нативный установщик независимым от Python.

## Что не является runtime-зависимостью

GitHub, shields.io и ссылки на каталоги моделей находятся в исходниках/документации
и не требуются для запуска уже установленной программы.

Сертификаты НУЦ Минцифры и документация Sber API тоже являются внешними источниками
только для настройки инфраструктуры. Они не загружаются автоматически самим
языком.
