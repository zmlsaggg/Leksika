# Контракт самостоятельного движка Лексики

**Состояние:** проект спецификации 0.1. Это целевой договор для нового исполнения, а не заявление, что описанные части уже реализованы.

## Зачем нужен этот документ

Лексика должна определять собственное поведение. Ни Python, ни C, ни другой язык реализации не должны определять смысл значений, операций, областей видимости, ошибок и программного интерфейса.

Сейчас в репозитории есть две переходные реализации:

- файлы `лексика/*.lek` и `лексус.lek` фактически написаны на синтаксисе Python. Загрузчик читает их и передаёт встроенному компилятору Python. Расширение `.lek` само по себе не делает эти файлы программами на языке Лексика;
- `ядро/лексус.c` — загрузочный нативный инструмент: проверяет UTF-8, разбирает исходный текст, знает таблицу служебных слов и выполняет первую генерацию именных форм. Он пока не исполняет программы целиком.

Также нынешняя `лексика/машина.lek` не является самостоятельной виртуальной машиной: она передаёт вычисление выражений старому исполнителю, а часть вызовов правил обрабатывает через дерево грамматики.

Эти реализации нужны, чтобы сохранить работоспособную версию и переносить её по частям. Но **источником истины становится этот контракт и тесты языка**, а не поведение Python или особенности C.

## 1. Принципы

1. **Смысл принадлежит Лексике.** Типы, преобразования, сравнения, арифметика и ошибки описываются правилами языка.
2. **Исходник остаётся исходником Лексики.** Встроенные части движка в конечном счёте должны быть написаны обычными программами `.lek`, а не замаскированным Python или C.
3. **Нет обязательного языка реализации.** C11 сейчас допустим только как временная загрузочная ступень. Rust, Go или Python не назначаются ему постоянной заменой.
4. **Нет утечки устройства машины в язык.** Пользователь не видит указатели, адреса памяти, размеры машинных слов, устройство структур, исключения хост-языка или его коллекции.
5. **Поведение переносимо.** Одна программа даёт одинаковый результат на Windows, Linux и macOS.
6. **Совместимость проверяется примерами.** Переходная версия может быть эталоном для сравнения, но не определяет новые правила автоматически.
7. **Сначала смысл, потом оптимизация.** Быстрый код не оправдывает изменение результата программы.

## 2. Собственные виды значений

Исполняющий движок оперирует закрытым набором видов. Внешние представления Python или C не являются частью договора.

| Вид Лексики | Назначение | Правила |
|---|---|---|
| `ничто` | отсутствие значения | отдельный вид, не равен нулю и пустой речи |
| `истина` | логическое да или нет | два значения: `да` и `нет`; это не числа |
| `число` | целые и дробные числа | точная десятичная модель, описанная ниже |
| `речь` | текст | последовательность символов Unicode |
| `перечень` | упорядоченная коллекция | сохраняет порядок, допускает изменение |
| `словарь` | сопоставление ключей и значений | сохраняет порядок добавления ключей |
| `правило` | вызываемое действие языка | имеет параметры, область видимости и результат |
| `действие среды` | встроенная возможность движка | доступна только через явно определённые команды |

Нельзя определять вид значения проверкой принадлежности к типам языка реализации. Например, логическое значение не должно случайно считаться числом лишь потому, что так устроена базовая библиотека хост-языка.

### Числа

Число имеет один из двух математических видов:

- **целое** — знак и произвольное количество десятичных цифр;
- **дробное** — знак, целая часть и точная десятичная дробная часть.

Целые числа не переполняются на границе 32- или 64-разрядного машинного слова. Ограничение памяти может остановить вычисление с понятной ошибкой, но не меняет значение молча.

Сложение, вычитание и умножение выполняются точно. Дробная часть хранится в десятичном, а не двоичном виде. Деление выдаёт не более 34 знаков после запятой и округляет остаток по правилу «к ближайшему, при равенстве — к чётному». Нули в конце дробной части не меняют значение и не обязаны выводиться.

Деление на ноль — ошибка смысла. Остаток от деления на ноль — такая же ошибка. Отрицательная степень числа даёт дробное значение. Преобразование к целому отбрасывает дробную часть в сторону нуля; `округлить` использует то же правило округления, что и деление.

В выводе дробная часть отделяется запятой: `12,5`. Внутренний формат числа не зависит от локали операционной системы.

### Логика и преобразования

`да` и `нет` — самостоятельные логические значения. Они не являются числами `1` и `0`. Равенство логического значения числу ложно; при необходимости пользователь явно вызывает `число(да)` или `число(нет)`.

Ложными в условии считаются только: `нет`, `ничто`, числовой ноль, пустая речь, пустой перечень и пустой словарь. Все остальные значения истинны. Это отдельное правило Лексики, а не вызов универсального преобразования хост-языка.

Преобразование речи в число разрешено только явным действием `число(речь)`. Неудачное преобразование даёт ошибку с исходным значением и местом в программе.

### Речь и коллекции

Речь хранится как последовательность кодовых точек Unicode. Её длина не равна
числу байтов UTF-8, элементов UTF-16 или графем: например, буква с отдельным
комбинируемым знаком учитывается как две кодовые точки. U+0000 допустим внутри
речи и не завершает её. Некорректные последовательности UTF-8 отклоняются на
границе ввода.

Индексация перечня начинается с нуля. Выход за границу перечня и обращение к
отсутствующему ключу словаря дают ошибку смысла. Перечни сравниваются
структурно и с учётом порядка элементов. Словари сравниваются по набору
ключей и значений без учёта порядка добавления пар.

Ключом словаря могут быть речь, число и логическое значение. Числовые ключи
сравниваются по числовому значению: `1` и `1,0` — один ключ. Значения разных
видов не смешиваются: например, ключ `да` отличается от ключа `один`.
Перечни, словари и правила ключами не являются.

Перечни и словари являются изменяемыми объектами со ссылочным поведением:
копирование значения коллекции не копирует её содержимое. Циклические графы
коллекций запрещены; попытка прямого или косвенного самовложения вызывает
ошибку смысла. Это позволяет использовать простое управление временем жизни
объектов без недоступных циклов.

Плюс для двух чисел означает сложение, для двух речей — соединение, для двух
перечней — объединение в новый перечень. Смешивание разных видов не приводит
к скрытому преобразованию: для преобразования используется явное действие
языка.

## 3. Области видимости и правила

- Каждое имя принадлежит конкретной области видимости.
- Чтение ищет имя от внутренней области к внешней.
- Объявление создаёт имя в текущей области.
- Присваивание меняет ближайшее уже объявленное имя; если такого имени нет, движок сообщает об ошибке, а не создаёт его незаметно.
- Вызов правила создаёт отдельную область параметров.
- Правило видит область, в которой оно было объявлено, а не случайную область вызывающего кода.
- Параметры передаются по значению для простых значений; перечни и словари остаются ссылочными объектами с определёнными выше правилами изменения.
- Возврат, прерывание и продолжение — отдельные управляющие действия языка. Они не моделируются исключениями хост-языка.

Это целевое поведение. Перед его включением в основной движок оно должно быть покрыто тестами, в том числе на вложенные правила и рекурсию.

## 4. Ошибки

Ошибка движка — собственное значение с полями:

- вид: письмо, грамматика, падеж, смысл, среда или ресурс;
- сообщение;
- файл;
- строка и столбец;
- необязательная подсказка.

Внутренний механизм реализации может использовать любой способ передачи ошибок, но наружу выдаётся только описанная форма. Ошибки не должны содержать стек вызовов Python/C, адреса памяти или имена внутренних функций хост-языка.

## 5. Путь от исходника до исполнения

Целевой конвейер:

```
исходник .lek
    ↓
лексический разбор
    ↓
нормализация слов и морфологический разбор
    ↓
грамматика и дерево смысла
    ↓
сборка всех выражений в собственные команды
    ↓
проверка программы и таблиц имён
    ↓
виртуальная машина Лексики
    ↓
действия стандартной среды
```

Дерево смысла — временное представление компилятора. Оно не передаётся в исполнение и не хранится в командах байткода. В байткоде должны быть только константы, номера имён, команды и адреса переходов.

## 6. Начальный набор команд машины

Названия ниже — смысловые имена команд. Числовые коды и окончательная двоичная упаковка фиксируются отдельно, после того как набор пройдёт тесты.

| Команда | Эффект |
|---|---|
| `положить_константу` | поместить константу на вычислительный стек |
| `прочитать_имя` | найти имя и поместить его значение на стек |
| `объявить_имя` | объявить имя, забрав значение со стека |
| `записать_имя` | изменить ближайшее объявленное имя |
| `сложить`, `вычесть`, `умножить`, `разделить` | взять два значения, применить правила чисел |
| `остаток`, `степень` | числовые действия |
| `сравнить` | сравнить два значения по правилам Лексики |
| `не`, `и`, `или` | логические действия |
| `создать_перечень`, `создать_словарь` | создать собственную коллекцию |
| `взять_элемент`, `записать_элемент` | чтение и изменение коллекций |
| `показать`, `спросить` | взаимодействие через среду |
| `перейти`, `если_нет` | управление ходом программы |
| `войти_в_область`, `выйти_из_области` | управление видимостью имён |
| `вызвать`, `вернуть` | вызов правила и возврат результата |
| `завершить` | завершить текущую программу |

Для каждой команды будут описаны количество значений до и после выполнения, допустимые виды, поведение при ошибке и источник позиции в исходнике. Команда не может содержать объект дерева смысла, адрес памяти или функцию хост-языка.

## 7. Стандартная среда и граница платформы

Логика языка не обращается напрямую к файловой системе, часам, случайности или процессам. Она запрашивает именованное действие среды. Среда проверяет разрешения и возвращает собственное значение или ошибку.

Минимальные группы действий:

- ввод и вывод;
- чтение и запись файлов;
- время;
- случайные числа;
- загрузка частей программы;
- завершение процесса.

Позже для файлов, сети, запуска процессов и окружения появится явная модель разрешений. Сам факт наличия действия в стандартной среде не означает, что оно разрешено каждой программе.

Операции с памятью, строки, коллекции и числа принадлежат движку и не должны выдаваться за платформенные действия.

## 8. Что не является частью языка

В пользовательском синтаксисе и семантике не должно быть зависимости от:

- Python-значений `None`, `bool`, `int`, `float`, `list`, `dict` и его исключений;
- C-типов `long`, `double`, `char*`, указателей и соглашений о размещении структур;
- библиотек импорта и загрузки модулей чужого языка;
- машинного порядка байтов, размера указателя или разрядности процессора;
- локали операционной системы для чисел и текста.

Это не запрет использовать низкоуровневые механизмы при реализации. Это запрет делать их поведение правилом языка или обязательной зависимостью поставки.

## 9. Приёмка независимого движка

Переход считается завершённым только когда:

1. Все выражения компилируются в собственные команды без передачи узлов дерева старому исполнителю.
2. Машина исполняет примеры и тесты без обращения к Python.
3. Числа, речь, коллекции, области видимости и ошибки совпадают с этим контрактом на Windows, Linux и macOS.
4. В установке нет встроенного Python и нет требования установить Python.
5. Компилятор и стандартная библиотека постепенно переписаны на обычном синтаксисе Лексики.
6. Загрузочная реализация может собрать следующую версию компилятора, а та — повторно собрать себя с тем же результатом.

Только после этого Python можно удалить из рабочего пути. C-компилятор тоже не должен требоваться пользователю при установке или запуске. C остаётся лишь исторической загрузочной ступенью до тех пор, пока собственная цепочка сборки не сможет заменить её.

## 10. Проверочные примеры контракта

Это минимальные ожидаемые результаты для будущего общего набора тестов.

| Программа / действие | Ожидаемый результат |
|---|---|
| `два плюс три` | целое `5` |
| `один разделить на два` | дробное `0,5` |
| `один разделить на три` | дробное с 34 знаками после запятой, округление к чётному |
| `да равно один` | `нет` |
| `пустая речь` в условии | `нет` |
| длина речи из двух кириллических букв | `2`, независимо от UTF-8 |
| индекс `перечня` за его границей | ошибка смысла с позицией |
| чтение отсутствующего имени | ошибка смысла, без автоматического объявления |
| деление на ноль | ошибка смысла, без аварийного завершения процесса |

Пока контракт имеет статус проекта: несовместимые с ним изменения действующего эталона должны обсуждаться явно, а не приниматься незаметно из-за особенностей одной реализации.


## Политика действий среды в нативной VM

Каждая подключённая среда выдаёт VM явный набор capabilities:
`ВВОД`, `ВЫВОД`, `ФАЙЛ_ЧТЕНИЕ`, `ФАЙЛ_ЗАПИСЬ`, `СЕТЬ`, `ПРОЦЕСС`,
`СЕКРЕТЫ`. Ноль разрешений означает запрет действий. Перед вводом и выводом
сама VM проверяет capability, а затем при наличии вызывает callback политики
для проверки конкретного ресурса и аудита. Стандартный доверенный запуск
через stdin/stdout сохраняет отдельный совместимый путь.

Файловые, сетевые, процессные и секретные операции пока не реализованы в
нативной стандартной среде; соответствующие capability зарезервированы, но
не считаются готовой защитой до появления самих операций и их тестов.
