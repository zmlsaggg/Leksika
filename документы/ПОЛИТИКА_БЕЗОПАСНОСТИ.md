# Политика безопасности Лексуса

Лексус теперь имеет два режима работы.

## Обычный

Обычный режим сохраняет совместимость с существующим проектом. Сеть всё равно
не разрешена по умолчанию: для сетевого поиска требуется отдельное разрешение
в политике и отдельная настройка языка.

Файловые операции и локальные внешние процессы остаются совместимыми со старым
runtime. Чувствительные действия попадают в локальный аудит.

## Защищённый

В защищённом режиме по умолчанию закрыты:

- сеть;
- запуск внешних процессов;
- сторонние Python-модули;
- чтение и запись вне разрешённых корней.

Аудит включён принудительно.

Пример:

    лексус безопасность
    лексус безопасность режим защищённый
    лексус безопасность путь C:\Проекты\Банк\приложение
    лексус безопасность узел api.example.ru
    лексус безопасность процесс llama-cli
    лексус безопасность модуль llama_cpp
    лексус безопасность секрет СБЕР_ПАРОЛЬ

Для сетевого поиска нужны два разрешения:

    лексус безопасность сеть да
    лексус настройка разрешить_поиск_в_сети да
    лексус настройка сетевой_провайдер duckduckgo

По умолчанию сетевой провайдер равен «нет».

## Аудит

Журнал:

    ~/.lek/аудит.логе

Команда:

    лексус аудит
    лексус аудит --проверить

Команда с `--проверить` проходит всю цепочку и сообщает номер повреждённой
записи, если отпечаток или связь с предыдущей записью нарушены.

Каждая запись содержит SHA-256 цепочку, связывающую её с предыдущей записью.
Это обнаруживает изменение середины файла при последующей проверке, но не
защищает файл от владельца ОС, который может удалить или заменить весь журнал.

Содержимое секретов в журнал не записывается.

## Секреты

Секреты не должны храниться в .lek, настройках или README.

Переходный интерфейс:

    from лексика import секреты
    пароль = секреты.получить("СБЕР_ПАРОЛЬ")

CLI намеренно показывает только наличие:

    лексус секрет СБЕР_ПАРОЛЬ

В защищённом режиме имя должно быть в разрешённые_секреты.

Это не HSM и не полноценное системное хранилище ключей. Нативный backend для
Windows DPAPI, Linux Secret Service, macOS Keychain и корпоративных HSM остаётся
следующим этапом.

## Границы текущей защиты

Текущий Python runtime всё ещё является переходной средой. Поэтому защищённый
режим ограничивает наши собственные API и точки входа, но не превращает Python
в полноценную песочницу.

Пока программа может загрузить произвольный Python-код через сам переходный
runtime, нельзя считать систему сертифицированным изолированным исполнителем.

Целевой нативный VM должен перенести эти проверки внутрь самой среды исполнения,
чтобы программа не могла обойти policy через хост-язык.
