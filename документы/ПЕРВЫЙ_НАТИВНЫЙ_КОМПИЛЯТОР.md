# Первый нативный компилятор Лексики

## Что реализовано

Нативный компилятор переводит небольшой согласованный с грамматикой Лексики набор действий в регистровый байткод. После компиляции VM работает только с инструкциями, константами и регистрами; дерево разбора и объекты AST в неё не передаются. Обычные значения обрабатываются модулем `ядро/значения.c`.

Путь исполнения:

1. Чтение UTF-8 исходника.
2. Разбор поддерживаемых конструкций и русских имён.
3. Построение таблицы точных числовых констант и регистровых инструкций.
4. Проверка каждого opcode, регистра и индекса константы.
5. Исполнение в собственной VM с ограничением числа шагов.

## Поддерживаемый синтаксис

```лексика
пусть счёт равно ноль.
повторить два раза
увеличить счёт на один.
конец повторить.
пока счёт меньше три повторять
увеличить счёт на один.
конец пока.
если счёт равно три то
сказать речь Готово! конец речи.
иначе если счёт больше три то
сказать речь Слишком много конец речи.
иначе
сказать речь Не получилось конец речи.
конец если.
```

Поддерживаются:
- объявление `пусть имя равно выражение.`;
- изменение `увеличить/уменьшить/умножить/разделить имя на выражение.`;
- вывод `сказать выражение.`;
- ветвления `если … то … иначе если … иначе … конец если`;
- циклы с предусловием `пока … повторять … конец пока`;
- счётные циклы `повторить число раз … конец повторить`, включая вложенность;
- возврат из любой ветви условия или цикла;
- циклы `прервать` и `продолжить`, включая вложенные циклы;
- обход перечней `где имя из перечень повторять` и `для каждого имя из перечень повторять` с локальной переменной;
- `спросить` и `что` через инъецируемый интерфейс ввода/вывода среды;
- `почему условие то причина` для проверяемого утверждения VM;
- простые UTF-8-блоки `речь … конец речи`.
- возврат `вернуть выражение.`;
- целые и десятичные литералы цифрами, 126 словоформ числительных и 19 форм множителей (тысячи, миллионы, миллиард); дробная часть через «запятая»;
- простые речевые литералы `речь … конец речи`, хранение UTF-8 с явной длиной и соединение речевых значений;
- русские имена переменных и скобки;
- унарные «минус» и «не», арифметика с приоритетом умножения/деления;
- равенство, неравенство, числовые сравнения `больше`/`меньше`, включая формы `не больше`, `не меньше` и `больше/меньше или равно`;
- логические `и` и `или`, а также значения `да`, `нет` и `ничто`. В этой версии
  обе стороны логического выражения вычисляются; короткого замыкания пока нет.

## Ограничения первого среза

Доступно не более 254 переменных на программу: два из 256 регистров зарезервированы для вычислений. Проверка видов значений для арифметики и сравнения выполняется VM во время исполнения. Логические `и` и `или` пока вычисляют обе стороны выражения, короткого замыкания нет. Счётчики `повторить` хранятся в отдельном стеке VM, поэтому вложенные циклы не расходуют регистры пользовательских переменных. Вложенность управляющих блоков ограничена 128 уровнями; 129-й уровень отклоняется диагностикой вместо переполнения стека компилятора. Это отдельно проверяется интеграционным тестом. Дробное количество повторений усекается к целому по правилу `int()`; нулевые и отрицательные количества пропускают тело.

Это ещё не вся грамматика Лексики. Не поддерживаются интерполяция выражений внутри речи, вызовы пользовательских правил и кадры вызовов, словари, модули, полноценное падежное разрешение имён и файловая стандартная библиотека. `прервать`/`продолжить`, ввод/вывод и перечни уже работают в нативной VM для описанного подмножества. Компилятор сообщает об неподдерживаемой конструкции и не делегирует её Python.

Вычисления выполняются собственными значениями и десятичной арифметикой Лексики, а не типом `double`. VM не зависит от Python во время исполнения этого подмножества. Само ядро пока собирается временным C11-bootstrap; самохостинг остаётся отдельной задачей.

Для Windows PowerShell после установки GCC из MSYS2 UCRT64 можно выполнить
сборку без GNU Make:

```powershell
powershell -ExecutionPolicy Bypass -File .\сборка\проверить_нативный_компилятор.ps1
```

Скрипт собирает нативное ядро и группы тестов, запускает проверочный пример.
Полная сборка словарного индекса выполняется отдельной командой и здесь
намеренно не запускается.

## Сборка и проверка

Из корня репозитория:

```sh
make -C ядро лексус-ядро
./ядро/лексус-ядро выполнить примеры/нативная_vm.lek
make -C ядро компилятор-тест
./ядро/компилятор-тест
```

Ожидаемый вывод примера:

```text
Готово!
```

Полный набор:

```sh
make -C ядро test
```

Тесты проверяют приоритет операций, объявления и изменение переменных, возврат результата, деление и деление на ноль, скобки, десятичную запятую, числительные словами (десятки, тысячи, миллионы, миллиард и дроби), речевые литералы, соединение речи, незакрытые блоки речи, сравнения, логические операции, истинную и ложную ветви, цепочки `иначе если`, возврат из ветвей и из циклов, циклы `пока` и `повторить` (включая вложенные, нулевые, отрицательные и дробные счётчики), `прервать`/`продолжить`, обход `где` и `для каждого`, локальную область переменной цикла, ввод/вывод среды, утверждения `почему`, очистку стека циклов, ограничение вложенности управляющих блоков (129-й уровень отклоняется), повторное использование двух регистров на длинном выражении и отказ от необъявленных или латинских имён.


## Разговорные профили

Нативный CLI поддерживает ограниченный набор командных синонимов двух разговорных профилей. Они выключены по умолчанию:

```text
лексус-ядро выполнить пример.lek --профиль=18+
лексус-ядро выполнить пример.lek --профиль=зумер
```

Можно указать оба флага одновременно. Нативная таблица синонимов сверяется с
общим `данные/словарь/разговорные_слова.json`; браузерная песочница читает этот
же JSON. Проверка соответствия:

```sh
python3 проверка/профили_синхронизация.py
```

На этом этапе нативно переносятся только синонимы команд, которые уже есть в
C11-подмножестве. Профильные существительные, грамматические признаки,
падежное разрешение и синхронизация пользовательских настроек между
настольным приложением и браузером пока не перенесены.
